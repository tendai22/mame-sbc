# ビルド環境整備

Windows マシンに WSL - Ubuntu を入れてビルド環境を整備する。

大まかな流れは、

1. WSL のインストール
2. VScode のインストール
3. gitのインストール
4. git-credential-manager のインストール
5.  gcc のインストール
6.  その他ビルドツール(make, ...)

新しいマシンでWSLを入れるところから記録をとり、記録を整理して以下の手順をまとめた。

## 1. wslを入れる

> Ubuntu-22.04, 24.04 にしておいたほうがよい。
> * 18.04 の場合、gcc の必要バージョンが入らない。別途自前でビルドが必要になる。
> * 20.04 の場合、SDL2周りでリンクエラーが出る。パッケージの SDL2 が古すぎるのだろう。

* BIOSで、VT-d を enable にした。
* 管理者モードでPowerShellを起動して、`wsl.exe --install`とたたく。

```
> wsl.exe --install Ubuntu-22.04
```

* 再起動してログインすると、Terminalに wsl2が起動した。
  + ここでWSL上のユーザ名、パスワードが決まる。

* Ubuntu 24.04が入った。


## 2. VScodeを入れる

> VScode は、まず Windows 版をインストールすること。先に WSL 内部に入れるとおかしなことになる。

* Windowsにインストール: PowerShellから

```
winget install -e -id MicrosoftVisualStudioCode
```

* apt -y update
* apt -y upgrade
* Windows側でVScodeを起動し、"Remote Development" 拡張機能をインストール
* Linux側に`code`をインストール:  
  `sudo snap install code`ではエラーが出る。
* `sudo snap install code --classic`でインストール。
* `code .`でVScodeが起動する。
* 日本語化: `Japanese Language Extensions`をインストール、再起動。
* 白モード: Ctrl-Shift-pでコマンドプロンプトを出して`light`とたたくと白黒反転コマンドが選べる。


### 旧マシンで Ubuntu 24.04を入れた時の話

* Ubuntu-24.04を入れた。
* 別環境、ホームフォルダも新規
* apt -y update
* apt -y upgrade

## 3. git のインストール

```
$ sudo apt-get install git
```

gitの設定は、git-credential-manager をインストールしてから行う。


## 4. git-credential-manager のインストール

> 2024年10月ぐらいから dotnet-sdk-8.0 対応となり、dotnet-sdk-7.0 インストールは不要になった様子。

github.com リポジトリを使って開発する場合、成果をリモートリポジトリに push せねばならない。パスワード認証でもかまわないが、面倒くさいので、git-credential-manager を使えるようにする。

git-credential-manager を使うと、ブラウザで github.com にログインしておくと、。あとは「小さな窓」が表示されて勝手に認証が成立し、push できるようになる。

* dotnet-sdk-8.0 を入れる。

```
$ sudo apt-get install dotnet-sdk-8.0
$ sudo apt install aspnetcore-runtime-8.0
```

* dotnet コマンドを使って git-credential-manager をインストールする。

```
$ dotnet tool install -g git-credential-manager
# インストールされているかのチェック
```

`.bash_profile`にPATHを追加しろと言われた。

```
$ cat .bash_profile
# Add .NET Core SDK tools
export PATH="$PATH:/home/kuma/.dotnet/tools"
```

`git-credential-manager configure` で初期設定が書き込まれる。

```
$ which git-credential-manager
# 初期設定 (.gitconfigに書き込まれる）
$ git-credential-manager configure
```

device/personal access tokenしか選択肢が出てこなかった。結局personal access tokenを使った。

LAURELEYでのインストールでは何も出ない。大丈夫か？とりあえず先に進む。

```
kuma@LAURELEY:~$ which git-credential-manager
/home/kuma/.dotnet/tools/git-credential-manager
kuma@LAURELEY:~$ git-credential-manager configure
Configuring component 'Git Credential Manager'...
Configuring component 'Azure Repos provider'...
kuma@LAURELEY:~$
```

### credentialStore = cache

`.gitconfig` に `credentialStore = cache` を入れておく。

```
[credential]
        credentialStore = cache
        cacheOptions = --timeout 300
        helper = /home/kuma/.dotnet/tools/git-credential-manager
```

### xdg-open コマンドで認証状態を確認

```
xdg-open https://github.com/tendai22/
```

でブラウザを起動するようにしないといけない。ブラウザはWindows版exeを起動する。

xdgのブラウザ定義は、ファイル`~/.local/share/applications/chrome.desktop`を作り、以下の内容を入れておく。

```
[Desktop Entry]
Encoding=UTF-8
Version=1.0
Type=Application
NoDisplay=true
Exec=/home/kuma/bin/chrome.sh
Name=Chrome
Comment=Microsoft Chrome
MimeType=x-scheme-handler/unknown;x-scheme-handler/about;x-scheme-handler/https;x-scheme-handler/http;text/html;
```

シェルスクリプト `chrome.sh` を作る。手元のローカル環境でよい。

> https://qiita.com/Ryusuke-Kawasaki/items/3ca0e9674ec41238ab8e
にそんなことが書いてあるような気がする。

```
#! /bin/sh
#! /bin/sh
exec "/mnt/c/Program Files/Google/Chrome/Application/chrome.exe" "$@"
```

> `Exec`の値に空白が含まれると起動しない。エスケープもできず、結局空白なしのファイル `chrome.sh` を仕立てたわけだ。

* git-credential-helper をインストールする。

ソースを入れてビルドする方法と、debファイルをダウンロードして入れる方法とあるようだ。今回はdebファイルをインストールしたが。

### .git/config の設定

`git config -l` で出てくる設定。リポジトリごとにリモートURLが異なる環境では、リポジトリの最上位ディレクトリの `.git/config` を書き換える。

```
[remote "origin"]
        url = https://github.com/tendai22/mame-sbc
        fetch = +refs/heads/*:refs/remotes/origin/*
[credential "https://github.com"]
        helper = /home/kuma/.local/bin/git-credential-manager
```

`credentialStore` の値についてはいろいろ言われているが、現在使用中のリポジトリでは設定していない。それでも動いている。ふつうは、`cache` を設定しているようだが。

```
        credentialStore = cache
```

リモートリポジトリごとに名前が異なる場合、リポジトリの '.git/config' に書けばよい。

```
[user]
        name = Norihiro Kumagai
        email = tendai22plus@gmail.com
```

## GCC のインストール

> To compile MAME, you need a C++17 compiler and runtime library. We support building with GCC version 10.3 or later and clang version 11 or later. MAME should run with GNU libstdc++ version 10.3 or later or libc++ version 11 or later. The initial release of any major version of GCC should be avoided. For example, if you want to compile MAME with GCC 12, you should use version 12.1 or later.

mame のビルドには、GCC Version10.3 以上が必要。Ubuntu-18.04 では gcc Version 9 だったので、gcc-12 のビルドが必要だった。Ubuntu-20.04 以後なら gcc はいれたものそのままで使えるらしい。

> ただし、SDL2 のバージョンが古すぎるとビルドできないようだ。Ubuntu-20.04 ではビルドが通らなかったような記憶がある。Ubuntu-22.04, 24.04 にしておいたほうがよさそう。

### apt-get で入れてみる。

最近の Ubuntu なら、そのまま `apt-get install gcc` してみよう。それで Version 10.3 以上が入れば儲けもんだ。

Ubuntu-24.04 なら gcc-13 が入るようだ。Ubuntu-22.04 なら gcc-12?

手順概略は、

* gcc-12を入れた。(gcc-11以上が必要)

* 必要なツールを入れる。make を入れた。
* sudo ln -s /usr/bin/gcc-12 /usr/bin/gcc

#### gcc-12を入れる。

```
$ sudo apt-get install gcc-12
```

#### 必要なツールを入れる。

[mameのビルドページ](https://docs.mamedev.org/initialsetup/compilingmame.html)
のDebian/Ubuntuの項目

```
$ sudo apt-get install git build-essential python3 libsdl2-dev libsdl2-ttf-dev libfontconfig-dev libpulse-dev qtbase5-dev qtbase5-dev-tools qtchooser qt5-qmake
```

GCC13-2が入るので、最初のgcc-12インストールは不要だったようだ。

#### cc/c++/g++ で所望のバージョンかを確認する方法

```
$ cc --vertion
$ c++ --version
$ g++ --version
```

### GCC-12 のビルド・インストール

#### 準備

* GNU make, flex, bison を事前に手でインストールしておく。  
  以下の download_prerequisites スクリプトでも入れてくれない。

半ば意図的に Ubuntu-20.44 を入れている。なので、apt-get install gcc で入る GCC は Version 12 ではない。手でインストールする。

#### インストール

[dsrevkovさんのスクリプト](https://gist.github.com/dstrebkov/ebe070c1e35d94f859c6cacae8d642ef)がよろしい。大まかな手順は

* `https://gcc.gnu.org/git/gcc,git`をcloneする。
* `remotes/origin/releases/gcc-12`をcheckoutする。
* `./contrib/download_prerequisites`(シェルスクリプト)を実行する。これで例の数値計算ライブラリ系のtarballがダウンロードされる。
* gcc-12-build ディレクトリをつくる。
* gcc-12-buildの下で configureを実行する。
  + --prefix=/home/kuma/opt/gcc-12.4.1 (手元にインストールする前提)
  + --enable-languages=c,c++,fortran,go
  + --disable-multilib
* make -j5
* make install (手元にインストールするので sudo不要)

#### パスを通す。

* .profile に /home/kuma/opt/gcc-12.4.1/bin を入れておくこと。
* LD_LIBRARY_PATH, LD_RUN_PATHの設定

```
# set envs for gcc-12.4.1
if [ -d "$HOME/opt/gcc-12.4.1/bin" ] ; then
    PATH="$HOME/opt/gcc-12.4.1/bin:$PATH"
fi
LD_LIBRARY_PATH=$HOME/opt/gcc-12.4.1/lib64
LD_RUN_PATH=$HOME/opt/gcc-12.4.1/lib64
export LD_LIBRARY_PATH LD_RUN_PATH
```

# 付録

## dotnet-dsk-7.0のインストール

git-credential-manager の動作には、かつては dotnet-sdk-7.0 が必要だった。その時に行ったインストール手順を残しておく。

[Ubuntu の .NET バックポート パッケージ リポジトリ](https://learn.microsoft.com/ja-jp/dotnet/core/install/linux-ubuntu#ubuntu-net-backports-package-repository)を見て入れる。

Ubuntu の .NET バックポート パッケージ リポジトリを登録する

```
$ sudo add-apt-repository ppa:dotnet/backports
```

Microsoft パッケージ リポジトリを登録する

packages-microsoft-prod.debをダウンロード、インストールする。そして`sudo apt update`

```
# Get OS version info which adds the $ID and $VERSION_ID variables
source /etc/os-release

# Download Microsoft signing key and repository
wget https://packages.microsoft.com/config/$ID/$VERSION_ID/packages-microsoft-prod.deb -O packages-microsoft-prod.deb

# Install Microsoft signing key and repository
sudo dpkg -i packages-microsoft-prod.deb

# Clean up
rm packages-microsoft-prod.deb

# Update packages
sudo apt update
```

これで普通にdotnet-sdk-7.0がインストールできる。

```
# 必要ならアンインストールする。
$ sudo apt-get remove dotnet-sdk-8.0

$ sudo apt upgrade dotnet-sdk-7.0
..
..(わちゃわちゃ入る)
..
$ sudo apt install aspnetcore-runtime-7.0
(既に入っているらしい)

$ dotnet --list-sdks
7.0.119 [/usr/lib/dotnet/sdk]
$ dotnet --list-runtimes
Microsoft.AspNetCore.App 7.0.19 [/usr/lib/dotnet/shared/Microsoft.AspNetCore.App]
Microsoft.NETCore.App 7.0.19 [/usr/lib/dotnet/shared/Microsoft.NETCore.App]
```

## VScode のインストールで失敗した場合

最初に Windows版 VScode をインストール、Remote - WSL Extensionをインストールするのだ。これで WSL内部で `code .`と叩くとうまくいく。

正しいインストール手順は、

* Windows版 VScode をインストール。
* Windows版 VScode を起動して、Remote - WSL 拡張機能をインストールする

ところが、先に Linux 環境で `apt-get install code` するとえらいことになる。 `code .` と叩くと起動するのが、X Window 版の VScode が入って起動されてしまう。

WSL の Xサーバ機能がすごすぎるということなのだが、

* 日本語文字が豆腐になる。`/usr/share/fonts/windows` にフォントファイルをコピー、`fc-cache`すると日本語文字は表示されるが `MS Gothic` で汚い。
* 日本語IME入力ができない。これは致命的。

```
$ sudo apt-get remove code
```

で Linux版を削除したが、今度は `code .`と叩いてもcodeが起動しない。

これは、`/mnt/c/Users/no-kumagai/AppData/Local/Programs/Microsoft VS Code/bin` にある `code`が vscode-server らしく、これを手で起動することでサーバのダウンロードが始まり、同時に PATH にも入った。

以後は `code .`と叩くと Windows版 VScode が起動して、日本語文字入力もできるようになった。

> Linux版remove後に、rehash していればよかったのかもしれない。もとから /mnt/c... はパスに入っていて、/usr/bin/code がなくなったので起動できないといわれていたように見えた。rehash も忘れるとは焼きが回ったもんだ。
